# MindCare — Project Context

Reference document for contributors and AI assistants. Describes what the project is, how it is built, and where the sharp edges are. Derived from reading the source.

## 1. Purpose
MindCare is an empathetic mental-health **support companion** (chat web app). It is explicitly *not* professional care. Crisis messages get a fixed safety reply with Indian helplines (1860 266 2345 / 9152987821). Built as a student project (IIIT Delhi).

## 2. Tech stack
- **Backend:** Python, Flask + flask-cors (`app.py`). Legacy/alternate FastAPI entry (`main.py`, used by `vercel.json`) and Streamlit UI (`bot.py`).
- **Models (local, Hugging Face):** emotion = `joeddav/distilbert-base-uncased-go-emotions-student` (28 labels); crisis confirmation = `facebook/bart-large-mnli` (zero-shot); retrieval embeddings = `sentence-transformers/all-MiniLM-L6-v2`.
- **Reply generation:** Gemini (default, flash-only), or HF Inference API, or local HF weights (`tanusrich/Mental_Health_Chatbot`, FLAN-T5 fallback).
- **Memory:** Redis (`REDIS_URL`) with automatic in-process fallback.
- **Frontend:** vanilla HTML/CSS/JS in `frontend/` (served by Flask at `/`, static at `/static`).

## 3. Request pipeline (`chatbot.chat`)
1. `detect_emotion` (DistilBERT GoEmotions) and `detect_crisis` run on every message.
2. **Crisis** → if `crisis.crisis`: store turn, return fixed `CRISIS_REPLY` (`crisis: true`). Generator is never called.
   - Crisis = regex keyword gate (`CRISIS_PATTERNS`) first; BART only confirms (labels `suicide risk`/`self-harm` need score ≥ 0.92, confirm ≥ 0.80) because BART alone over-fires on sadness/breakups.
3. **Retrieve knowledge:** `_best_intent` (keyword/alias scoring over `mindcare_dataset.json`, ~85 intents; breakup regex shortcut) + `retrieve_counseling` (MiniLM cosine over `counseling_rag.json`, top-k 2, min score 0.42, token-overlap fallback).
4. **Reply priority:** greeting template (`reply_source: template`, greetings only) → `generate_reply` (Gemini → optional failover) → `safe_fallback` / `dataset_fallback`.
   - RAG text is *never* returned raw; it only feeds the generation prompt (`_build_generation_prompt`: emotion, profile, rolling summary, knowledge, last turns).
5. Save turn, update rolling summary + structured profile, update/auto-title the conversation.

Response JSON includes debug fields: `emotion`, `crisis`, `reply_source`, `rag_hits`, `intent`, `memory_backend`, `generation`, optional `generation_error` / `failover_errors`.

## 4. Module map
| File | Role |
|---|---|
| `app.py` | Flask app: UI + API; warms models in a thread on startup |
| `chatbot.py` | Orchestration (`chat`, intent matching, prompt building, templates, fallbacks) |
| `emotion.py` / `crisis.py` | Emotion classifier / crisis gate |
| `rag.py` | Embedding retrieval + cache (`counseling_rag_embeddings.npz`), token fallback, `build_embedding_cache` |
| `generation.py` | `GeminiGenerator`, `HuggingFaceAPIGenerator`, failover order, system prompt, LLM conversation titles, `generation_status` |
| `memory.py` | `MemoryStore`: history (cap `MEMORY_MAX_TURNS`=40), extractive rolling summary after 12 turns keeping 8 recent, owner profile (concerns/triggers/what_helped via regex patterns), multi-conversation index per owner (max 40), title heuristics |
| `expand_dataset.py` | Builds/refreshes intents + ~2,500 counseling pairs (Amod dataset) + embedding cache |
| `evaluate.py` + `eval_cases.json` | Eval harness: suites project, emotion, crisis, rag, chat, memory, live |
| `llm_providers.py`, `main.py` | Older FastAPI/Gemini+intent path (Vercel); **not** used by `app.py` |
| `chatbot_local.py`, `bot.py` | Optional local HF loader; legacy Streamlit UI |
| `test.py` | Tiny CLI smoke script |
| `run.sh` | `ui|api|streamlit|test|eval|redis` launcher (loads `.env`, uses `.venv`) |

## 5. API (Flask)
`GET /`, `GET /api`, `GET /health`, `POST /chat`, `POST /clear`, `GET /chat_memory`, `GET /user_profile`, `GET|POST /conversations`, `GET|DELETE /conversations/<id>`, `POST /conversations/<id>/title` (LLM-polished title on leaving a chat).
Identity model: `owner_id` = browser id (profile + conversation list); `conversation_id` = history/summary key. Legacy `user_id`-only calls still work.

## 6. Configuration (`.env`, see `.env.example`)
`GENERATION_PROVIDER` (gemini|hf_api|local), `GEMINI_API_KEY`, `GEMINI_MODEL` (non-"flash" names are silently replaced by `gemini-flash-lite-latest`), `GEMINI_THINKING_LEVEL`, `GEMINI_TIMEOUT_SECONDS`, `HF_TOKEN`, `HF_CHAT_MODEL`, `GENERATION_FAILOVER` (default false), `FAILOVER_INCLUDE_LOCAL`, `REDIS_URL`, `MEMORY_*`, `RAG_BACKEND|RAG_EMBED_MODEL|RAG_TOP_K|RAG_MIN_SCORE`, `PORT` (default 5050; macOS uses 5000).

## 7. Data files
- `mindcare_dataset.json` — intent KB (committed).
- `counseling_rag.json`, `counseling_rag_embeddings.npz` — generated by `python expand_dataset.py`; **git-ignored**, so a fresh clone must run it (RAG degrades without it).
- `eval_cases.json` — golden eval cases.
- `Exploratory_Data_Analysis(EDA)` — Colab notebook JSON (no extension) from early dataset exploration.

## 8. Design decisions worth preserving
- Templates only for greetings; everything else goes through the generator for natural replies.
- Crisis path is deterministic and bypasses the LLM.
- Strict RAG thresholds after weak matches dumped irrelevant counseling text.
- Gemini is flash-only and fails fast (timeout) so chat stays responsive; local 7B failover is opt-in because loading can hang for minutes.
- Redis optional: app must work with in-memory fallback.

## 9. Known caveats / gotchas
- Two parallel backends exist (Flask `app.py` is the real one; FastAPI `main.py`/`llm_providers.py` is legacy and `vercel.json` points at it; the heavy local models make Vercel deployment impractical).
- README example model name `gemini-3.5-flash` vs `.env.example` default `gemini-flash-lite-latest`.
- No authentication: `owner_id` is client-supplied; anyone knowing an id can read that history. Don't deploy publicly without adding auth.
- Conversation text is stored in Redis in plain text; no TTL by default (`MEMORY_TTL_SECONDS=0`).
- Crisis detection is keyword-driven; it can miss indirect phrasing. Not clinically validated.
- Heavy dependencies (`torch`, `transformers`); first request downloads/loads models.
- No LICENSE file yet; dataset licences (Amod counseling data, original intents) apply to the JSON files.

## 10. Common commands
```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
python expand_dataset.py          # build RAG corpus + embeddings
cp .env.example .env              # add GEMINI_API_KEY
./run.sh ui                       # http://127.0.0.1:5050
./run.sh eval [--quick|--live|--suite rag,chat]
```
